How fast is Mokou?

Every release is measured against upstream Deno, Node.js and Bun on the same machine, with the same programs. The numbers below are for dev-0f77e520, run on 2026-10-14 at commit 0f77e520d2dc.

Intel(R) Xeon(R) Processor @ 2.10GHz, 16 GB RAM, 4 threads, linux x86_64

Mokou is a local build of the release profile (fat LTO, one codegen unit) relinked with the startup function order, as the release workflow does. Its size is of the packaged binary, with unwind sections removed. Upstream Deno 2.9.7, Node 22.22.0 and Bun 1.4.2 are the official binaries.

One shared 4-vCPU virtual machine, each benchmark measured three times with the runtimes taking turns, median reported. Differences under about 15% on the millisecond benchmarks are noise here.

  • Mokou mokou 0.1.0 (deno 2.9.7 base, stable, release, x86_64-unknown-linux-gnu), 102.0 MB binary
  • Deno deno 2.9.7 (stable, release, x86_64-unknown-linux-gnu), 95.8 MB binary
  • Node.js v22.22.0, 123.4 MB binary
  • Bun 1.4.2, 79.5 MB binary

How it is measured

Each benchmark is a small program in tests/bench/compare/cases that runs unchanged on every runtime and uses the fastest idiomatic API each one has: Deno.openSqlite() on Mokou, bun:sqlite on Bun, node:sqlite on Deno and Node. Times are the median of repeated runs; the server benchmark is requests per second under wrk -t2 -c64. Runtimes are the latest stable releases at the time. To repeat a run:

mokou run -A tests/bench/compare/run.ts --mokou ./target/release/deno --label v0.1.0 --json results.json

Results for every release are kept in results/ and this page is built from them by tests/bench/compare/page.ts.
